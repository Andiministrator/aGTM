# Glossar

aGTM-Domänenbegriffe. Bewusst wenige, präzise Einträge. Abgeleitet aus
`CLAUDE.md`, `README.md` und `SESSION-REDESIGN.md`.

| Begriff | Bedeutung |
|---------|-----------|
| **aGTM** | „a Galactic Tagging Modulator" — die JavaScript-Library (`aGTM.js`), die den Google Tag Manager erst nach Vorliegen der Cookie-Consent-Entscheidung lädt. ES5-only. Alles liegt unter einem Objekt: `aGTM` (`.c` Config, `.d` Runtime-Daten, `.f` Funktionen, `.l` Log). |
| **CMP** | Consent Management Platform (Cookie-Banner-Tool). Pro CMP eine Datei `cmp/cc_<name>.js`, die `aGTM.f.consent_check(action)` implementiert und das Ergebnis nach `aGTM.d.consent` schreibt. 25 CMPs in v1.5 (Cookiebot, CCM19, Usercentrics v2/v3, OneTrust, Klaro, …). |
| **sGTM / Server-side GTM** | Server-seitiger Google Tag Manager. Der **sGTM-Client** (`sgtmClient/`) ist ein GTM-Server-Template, das die aGTM-Library **und** die Session-/Consent-Daten in einer Response ausliefert und die server-seitigen Verträge (Session API, Promote, Sources, Consent-Store) bedient. |
| **Consent Mode** | Google Consent Mode (v2). GTM-Tags müssen über Consent-Signale gegated sein, damit ein nachträgliches `aGTM_consent_update` das Tag-Verhalten (drop/redact) tatsächlich ändert — Pflicht bei optimistischem Preset-Consent (SESSION-REDESIGN.md §7, M2). |
| **dataLayer** | Das GTM-Eingangs-Array (Default-Name `dataLayer`, Config `gdl`). aGTM pusht Events via `aGTM.f.sendnaus()` hinein. `aGTM.f.fire()` ist der externe Einstiegspunkt zum Eventversand. |
| **Consent-Store** | Phase-3-Mechanismus: aGTM difft den CMP-Consent gegen den server-bekannten Stand und POSTet nur **Änderungen** an `consent_store_url` (auto-gebaut als `<sgtm-host>/aGTMconsent`). Der sGTM-Client persistiert den Consent in den Session-API-Record. |
| **Consent-Hash / Diff** | `aGTM.f.consent_serialize(c)` erzeugt eine stabile, sortierte **Blacklist**-Serialisierung von `aGTM.d.consent` (ohne `gtmConsent`/`blocked`, ohne leere/null-Werte). `consent_hash` (advanced nur bei 2xx-POST) gated den Store-POST; `last_consent_hash` (advanced immer) gated `aGTM_consent_update` + Callback, damit der Poll nicht flutet. |
| **Attribution** | Keyed-by-Method-Objekt in `aGTM.d.attribution`, am Ende von `config()` aus `cfg.session.attribution` + aktueller URL/Referrer gemerged. HYBRID: URL gewinnt für browser-ableitbare Felder (`sou/cam/med/…`), API für Cross-Session-Memory-Felder (`afs/lcs/fss`). Z. B. `aGTM.d.attribution.last_touch.sou`. `aGTM.f.resolveAttribution(method)` liefert pro Methode. |
| **Session API (api4sgtm)** | Server-seitiger Dienst, der pro `(tenant, user_id)` den Session-Record (Counter, Consent) in geteiltem Redis hält. Liefert den Preset-`cfg.session` und nimmt Consent-/Promote-Writes entgegen. Spec in `internal/api/` (gitignored). |
| **Sources API (api4sources)** | Server-seitiger Dienst, der per `(tenant, session_id)` Quell-Daten (Landing-URL, Referrer) für spätere Attributions-Analyse (ClickHouse) speichert. Wird ausschließlich vom sGTM-Client fire-and-forget angesprochen — **die aGTM-Library ist nicht beteiligt**. |
| **GTM Custom Template (.tpl)** | GTM-Template im JSON-basierten `.tpl`-Format (Tag- und Variable-Templates in `gtm/`). Dateibenennung mit Leerzeichen (`aGTM tag - Click Events.tpl`). Liest u. a. `hastyEvents` zum Replay. |
| **noConsent-Container** | GTM-Container mit Option `noConsent: true`. Wird via `initGTM(true)` **vor** Consent injiziert; erhält `aGTM_ready` ohne Consent-Daten. Für funktionale/rechtliche Container, die unabhängig vom Consent laden dürfen. |
| **F→C promote** | User-ID-Aufwertung: ein Fingerprint-User `F.*` wird beim ersten echten Consent atomar (Redis TxPipeline via api4sgtm `/promote`) auf einen Cookie-User `C.1{lim}{tenant}{lim}{rand12}.{ms}` migriert. Literal `C.`-Prefix vom Promote-Validator erzwungen. Forward-Pfad (`/aGTMconsent`-POST) + Lazy-Pfad (`/aGTM.js`-GET für Altbestände). Library adoptiert `resp.uid` nur, wenn er mit `C.` beginnt (Race-Safety). |
| **ES5-Sandbox** | GTM führt Custom-Template-JS in einer Sandbox aus, die nur ECMAScript 5 unterstützt. Deshalb gilt ES5 für **alle** Repo-Files: `var` statt `let`/`const`, keine Arrow-Functions/Classes/Template-Literals. Minifizierung mit `terser --ecma 5 --keep-fnames`. |
| **hastyEvents / Queue-Replay** | Events, die via `aGTM.f.fire()` **vor** Consent gefeuert werden, landen in der Queue `aGTM.d.f`. Bei `inject()` wird `aGTM.d.f` als `hastyEvents` im `aGTM_ready`-dataLayer-Event übergeben; ein GTM-Template replayt sie, nachdem GTM geladen ist. |
| **Session-Status** | `aGTM.d.session_status` — Consent-Sync-Lifecycle: `""` (kein Preset), `"preset"` (cfg.session ohne nutzbaren Consent), `"preset_with_consent"` (Preset-Consent geseedet, GTM injiziert auf dem ersten Tick), `"synced"` (CMP-Änderung gediffed + erfolgreich POSTet), `"confirmed"` (CMP-Stand == Preset, kein POST nötig). |
| **POST-Transport** | Direkter HTTP-POST von Events an ein Backend, unabhängig von GTM. Steuerung global (`transport_url`/`transport_enc`/`transport_salt`) oder per Event (`_post`). `aGTM.f.xsend()` sendet, `aGTM.f.enc()` obfuskiert (Base64 + Caesar-Shift). |
| **`_noConsent` / `_noDLPush`** | Event-Properties in `aGTM.f.fire()`: `_noConsent` umgeht das Consent-Gate (DL-Push + POST sofort); `_noDLPush` überspringt den dataLayer-Push (kein GTM-Tag), loggt aber intern und sendet POST. Kombiniert: Pre-Consent-Transport ohne GTM-Trigger. |
| **Auto-Denial (server-seitig)** | Der sGTM-Client baut für wiederkehrende Besucher ohne gespeicherten Consent (`counter > 0`) server-seitig einen Denial-Consent (`services: ',aGTMconsent,'`, `blocked == gtmConsent`) und embedded ihn in `cfg.session.consent`. Eine echte CMP-Entscheidung gewinnt später via B2-Reset in `run_cc('update')`. |
| **B2-Reset** | Vor `consent_check('update')` werden CMP-verwaltete Felder von `aGTM.d.consent` genullt (Snapshot vorher), damit stale Preset-/Auto-Denial-Werte eine echte CMP-Entscheidung nicht überleben. Bei `consent_check === false` → Snapshot restore (macht den adaptiven Poll wiederholungssicher). |
| **Schritt-QA / Sprint-Abschluss** | Zweistufige QA: technische Prüfung pro Arbeitsschritt (`docs/qa/schritt-qa.md`: ES5, `bun test`, `./build.sh`, Doku-Sync) und Sprint-weite Konsistenz- + Release-Prüfung (`docs/qa/sprint-abschluss.md`: Abhängigkeits-Check, Kritiker-Sub-Agent, `v*`-Tag-Gate). |
